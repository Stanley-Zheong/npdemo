# 在线课程学习与考试系统 V1 测试用例

## 约定

证据基线为 `docs/prd.md` 和 `docs/delivery-plan.md`。staging 使用企微测试应用、PostgreSQL 和测试对象存储。每个修改用例从只读模板复制独立用户、课程和考试，资源名带用例 ID 和 run ID；不得依赖前一用例。草稿删除、授权撤销、课程归档；考试、证书和审计按运行 ID 隔离保留。

Lane 表示第一执行 owner：`API` 需后续自动化合同；`INT` 需真实/替身集成、可控时钟或任务触发；`UI` 需稳定页面元素；`SEC`、`PERF`、`RUNBOOK` 使用专项方案。均不表示当前已自动化。一个业务要求需要多 surface 证明时，先为每个 primary claim 建独立 case，再在自动化合同中记录关联 case。

进入自动化前，每个 case 必须补齐 fixture 模板标识、owner、创建命令、强回读、并行隔离和清理命令。缺少任一项时只能进入 `test-automation-contract` 或 `test-fixture-plan`，不得进入 spec generation。

## 自动化交接

进入自动化前，独立评审最终 UI/API/模型；为每例补齐接口/元素、fixture 所有权、并行隔离、强回读和清理；区分企微/存储/时钟/后台任务的替身测试与 staging 真实集成。只有各轴确定后才能标记 automation-ready。
